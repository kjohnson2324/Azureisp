THE COST OF LESS LIKELY


On May 2026's Patch Tuesday, Microsoft rated a SharePoint Server deserialization vulnerability as exploitation "less likely." On July 1, CISA added that same vulnerability, tracked as CVE-2026-45659, to its Known Exploited Vulnerabilities catalog, citing evidence of active exploitation in the wild. [1] The gap between those two assessments is eight weeks, and it is the story this issue is built around.

Two other developments arrived in the same window. Starting July 6, Microsoft began enforcing Conditional Access consistently at the moment of credential registration in Entra ID, closing a gap that has existed since Custom controls were introduced. [2] And Microsoft's Security Copilot Threat Intelligence Briefing Agent, now integrated directly into the Defender portal, is compressing the time between a threat intelligence signal and an analyst reading it from days to minutes. [3]

None of these three developments caused each other. But they describe the same underlying dynamic. The assumptions organizations make about risk, whether a vulnerability is exploitable, whether a registered credential is legitimate, whether a threat brief is timely, decay faster than the review cycles most security programs use to revisit them.


A RATING THAT DIDN'T HOLD


CVE-2026-45659 is a deserialization remote code execution vulnerability in SharePoint Server, carrying a CVSS score of 8.8. It affects SharePoint Server Subscription Edition, SharePoint Server 2019, and SharePoint Enterprise Server 2016. [1] Microsoft patched the vulnerability in its May 2026 security update, bringing SharePoint Server 2019 to build 16.0.10416.20004 and SharePoint Enterprise Server 2016 to build 16.0.5552.1002. [1] At the time, Microsoft's advisory rated exploitation as "less likely," a judgment that shaped how many organizations prioritized the patch against the rest of that month's update volume.

The technical detail that matters most operationally is that exploitation does not require administrative privileges. An authenticated attacker with nothing more than Site Member permissions, one of the lowest privilege tiers in SharePoint, can trigger the deserialization flaw and execute code remotely on the server. [1] That is a low bar. Any environment where SharePoint site membership extends beyond a tightly controlled group, which describes most enterprise SharePoint deployments, has a meaningfully larger population of potential entry points than a vulnerability requiring admin rights would.

CISA's KEV listing confirmed active exploitation and set a remediation deadline of July 4, 2026 for federal civilian executive branch agencies. [4] That deadline is a floor, not a ceiling. Any organization running on-premises SharePoint Server that has not confirmed its build number against the patched versions should treat that confirmation as an immediate priority, not a scheduled task. The build number check takes minutes. The exposure if it is skipped does not resolve itself.

The broader lesson is about how exploitation likelihood ratings age. Microsoft's severity assessments are informed by the information available at disclosure time. Proof of concept availability, criminal marketplace interest, and actual attacker behavior all develop after that point, sometimes within weeks. A patch prioritization process that treats the initial rating as permanent will miss the moment the calculus changes. A process that revisits unpatched vulnerabilities against updated threat intelligence, including CISA KEV additions, catches it.


ENTRA CLOSES THE REGISTRATION GAP


The second development is less dramatic than an actively exploited RCE, but it addresses a comparable class of gap: the moment a credential or device enrolls into the identity system in the first place.

Microsoft is retiring Custom controls in Entra ID Conditional Access in favor of External MFA. Custom controls retire on September 30, 2026, and reach end of life in May 2027. [2] The practical driver behind the deprecation is that Custom controls could not guarantee consistent Conditional Access enforcement across every registration path. External MFA closes that gap and integrates more directly with Entra's broader security capabilities.

Effective July 6, 2026, Conditional Access policies that target the Register security information action now also apply to Windows Hello for Business provisioning and macOS Platform Single Sign-on registration. [2] Before this change, those two enrollment paths sat outside the policies many organizations had built around credential registration, which meant a Conditional Access policy requiring, for example, a compliant device or a trusted location at registration time did not actually cover every way a credential could be registered. That inconsistency is now closed.

The third piece is a Self-Service Password Reset change. Microsoft began an SSPR registration campaign on July 6, 2026, prompting administrators and end users to register authentication methods ahead of enforcement. Starting September 7, 2026, SSPR will accept only authentication methods that have been explicitly registered. [2] Organizations that have relied on loosely defined or inherited authentication methods for password reset should use the window between now and September 7 to confirm that every account expected to use SSPR has completed explicit registration, not just eligibility.

Taken together, these three changes describe Microsoft narrowing the same category of exposure from three directions: the control mechanism, the enrollment paths it covers, and the authentication methods it accepts. Security architects should treat this as a prompt to audit Conditional Access coverage specifically at registration and enrollment events, not just at sign-in, which is where most CA policy review historically concentrates.


THREE ITEMS REQUIRING IMMEDIATE ATTENTION


1. Confirm SharePoint Server build numbers immediately. Any on-premises SharePoint Server 2019 or Enterprise Server 2016 deployment should be checked against the patched builds, 16.0.10416.20004 and 16.0.5552.1002 respectively. [1] Given the low privilege bar for exploitation and confirmed active exploitation in the wild, this is not a change to schedule into the next maintenance window. It is a change to verify without delay.

2. Audit Conditional Access coverage for registration and enrollment events. With policies targeting the Register security information action now extending to Windows Hello for Business and macOS Platform SSO as of July 6, security teams should confirm their existing registration policies actually apply as intended across all three paths, and begin migration planning away from Custom controls ahead of the September 30 retirement date. [2]

3. Evaluate the Threat Intelligence Briefing Agent for daily SOC workflows. The Security Copilot Threat Intelligence Briefing Agent, now integrated into the Defender portal in public preview, generates daily briefings that combine Microsoft's global threat intelligence with organization specific context, complete with risk assessments and links to affected assets. [3] For SOC teams whose current threat intelligence consumption is a manual review of vendor blogs and mailing lists, this closes exactly the kind of latency gap that let the SharePoint exploitation window run for eight weeks between disclosure and KEV listing. Teams that pilot it should measure it against a concrete question: would it have surfaced the SharePoint exploitation shift earlier than CISA's July 1 KEV addition did.


THE ROAD AHEAD


The pattern connecting these developments is not new to this series. Vol. 5 covered Purview Insider Risk Management for risky agents entering public preview with a general availability target of July 2026. That general availability rollout is now underway, reaching worldwide availability by the end of July. [5] The consistent thread across this series is that Microsoft's platform response and the threat landscape it responds to are both moving faster than the annual or quarterly review cycles many security programs still run on.

The SharePoint vulnerability shows what happens when a risk rating goes stale. The Entra registration changes show Microsoft closing a gap methodically, from three directions, ahead of a hard retirement date. The Threat Intelligence Briefing Agent shows the platform building the capability to close the assessment gap continuously rather than periodically. None of these are isolated stories. They are the same operating requirement expressed three different ways: reassess more often than the threat changes, not on a fixed schedule.

Organizations that treat vulnerability ratings, Conditional Access coverage, and threat intelligence consumption as periodic review items will keep discovering gaps the way CISA discovered this one, after the exploitation had already started.


FOR DISCUSSION

1. Microsoft rated CVE-2026-45659 as exploitation "less likely" in May 2026. CISA confirmed active exploitation eight weeks later. Does your vulnerability management process revisit initial severity and exploitability ratings against updated threat intelligence, or does the original rating stand for the life of the patch cycle?

2. The Entra Conditional Access changes effective July 6, 2026 close a gap between what registration policies were assumed to cover and what they actually covered. Has your organization audited its Conditional Access policies specifically for coverage at registration and enrollment events, separate from sign-in policies?

3. The Threat Intelligence Briefing Agent is designed to compress the time between a threat signal and an analyst acting on it. What is the current latency in your SOC between a vulnerability being added to a public exploitation catalog like CISA KEV and that information reaching the team responsible for patching?
