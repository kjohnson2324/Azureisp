THE PLAYBOOK EVERYONE SHARES


On July 31, 2026, Microsoft Threat Intelligence disclosed CaptiveCrunch, a campaign run by Storm-2945, an operational sub-cluster of Midnight Blizzard, the Russian SVR-linked actor also tracked as APT29. [1] Since early May, Storm-2945 has been compromising the captive portal infrastructure at hotels worldwide to intercept business traveler traffic and deliver a surveillance implant called CornFlake RAT. Since July 16, the same campaign has added a second stage: landing pages that walk victims through Microsoft's device code authentication flow, handing the attacker an MFA-satisfied session token without ever touching a password. [2]

That second technique is not new to this series. Vol. 9 covered Kali365, a criminal phishing-as-a-service platform using the identical OAuth device code abuse to hijack Microsoft 365 accounts, and recommended restricting the flow through Conditional Access. Three months later, a Russian state intelligence service is running the same technique against hotel Wi-Fi networks. The tradecraft did not stay contained to the criminal marketplace that popularized it.

Microsoft's David Weston gave that pattern a name at Black Hat USA on August 5. His keynote, titled "The End of Rare: Defending When Offense Is Cheap," argued that AI-powered vulnerability discovery and exploit generation are restructuring the basic economics of attack and defense: when a technique or an exploit can be found, automated, and reused at scale, the old assumption that defenders can simply patch faster than attackers can discover stops holding. [3] CaptiveCrunch is that argument made concrete. A technique proven against consumer accounts by a 250 dollar a month subscription service is now proven against Entra tenants by a state intelligence service, with essentially no development cost paid twice.

A smaller update closes the loop from Vol. 10. Project Perception, Microsoft's agentic vulnerability discovery and remediation system, entered public preview on August 3 as scheduled, and Microsoft is now positioning its underlying MAI-Cyber-1-Flash model directly against competing cybersecurity models from other major AI vendors on cost and benchmark performance. [4]


CAPTIVECRUNCH: HOTEL WI-FI AS A NATION-STATE ATTACK SURFACE


The technical mechanism behind CaptiveCrunch's first stage is what makes it distinctive. On the hospitality networks Storm-2945 compromised, the captive portal gateway also functioned as the DNS resolver assigned to every connected device. [2] Controlling that gateway let the attacker forge DNS responses for any domain, including the automatic connectivity check a laptop or phone runs when it joins a new network. Storm-2945 used that control to redirect the connectivity check to attacker infrastructure serving a fake browser or operating system update, which delivered CornFlake RAT to the traveler's device. [2] A guest joining hotel Wi-Fi and accepting what looks like a routine update prompt is, in this campaign, installing a nation-state surveillance implant.

The second stage, added mid-campaign on July 16, redirects some CaptiveCrunch landing pages into the device code authentication flow instead of, or in addition to, malware delivery. [2] The victim is directed to Microsoft's genuine device code entry page and prompted to enter a code the attacker generated, exactly as with Kali365's device code mode. The resulting session is authenticated, MFA-satisfied, and indistinguishable at the protocol level from a legitimate sign-in, because it is one. Microsoft Threat Intelligence notes technical and operational overlap between Storm-2945 and Storm-2372, a separate Midnight Blizzard sub-cluster that ran device code and OAuth code phishing operations throughout 2025, along with Microsoft Graph based email exfiltration. [1] The overlap suggests a shared, maturing toolkit moving between operational clusters within the same larger threat actor rather than a one-off technique borrowed from criminal use.

The operational implication for security teams is specific. Any organization with employees who travel and connect to hotel or venue Wi-Fi should treat captive portal networks as untrusted infrastructure capable of manipulating DNS, not merely as an inconvenient login page. Software update prompts served through a captive portal session should never be trusted, and travel policies that assume standard endpoint protection is sufficient on hotel networks are missing the specific mechanism this campaign exploits.


THE DEVICE CODE PROBLEM ISN'T GOING AWAY


CaptiveCrunch and Kali365 sharing the same core technique within a single quarter is evidence for a broader pattern Weston's keynote addressed directly: once an offensive technique works and gets automated, it moves fast, across actor types, because the cost of reusing it is close to zero. [3] Device code phishing is not a novel exploit requiring specialized development. It abuses a legitimate, documented OAuth flow that Microsoft built for genuinely limited-input devices. The barrier to a second actor adopting it is operational, not technical, and CaptiveCrunch shows that barrier has effectively disappeared.

This is the second consecutive issue of this series to recommend the same specific control: restricting or actively monitoring the OAuth device code authorization grant through Conditional Access, and reviewing sign-in logs for device code activity outside legitimate limited-input scenarios. Vol. 9 raised it in response to a criminal PhaaS platform. This issue raises it again in response to a state intelligence service. Organizations that made that change after Vol. 9 have already closed the specific gap both campaigns depend on. Organizations that have not now have two independent, unrelated threat actors demonstrating why it matters.

Weston's keynote framed the structural response as going beyond faster patching, toward memory safe languages, formal verification, and automated remediation built into the development pipeline itself. [3] Project Perception's public preview, and the direct cost and benchmark comparisons Microsoft is now drawing against competing cybersecurity models, are the company's first shipped answer to that framing. Whether that answer changes the device code exposure pattern in practice depends on adoption, not availability.


THREE ITEMS REQUIRING IMMEDIATE ATTENTION


1. Restrict OAuth device code authentication through Conditional Access if this has not already been done. With both a criminal PhaaS platform and a Russian state intelligence sub-cluster now confirmed using this technique against Microsoft 365 and Entra, treat the Vol. 9 recommendation as urgent rather than advisory, and audit sign-in logs specifically for device code grant activity. [1] [2]

2. Update travel security guidance to name captive portal DNS manipulation explicitly. Employees connecting to hotel or venue Wi-Fi should be instructed never to accept software update prompts served through a captive portal session, and should use a trusted VPN or cellular connection for sensitive access whenever traveling. [2]

3. Review Weston's Black Hat framing against your own patch and remediation cadence. If defense at your organization still assumes patching outruns discovery, the CaptiveCrunch and Kali365 overlap is direct evidence that assumption needs revisiting for identity-layer techniques specifically, not only for software vulnerabilities. [3]


THE ROAD AHEAD


This issue closes a loop that has been building since Vol. 8. AI-assisted discovery is producing more vulnerabilities than legacy triage can absorb. Attackers are persisting past patches through stolen material. Microsoft is now shipping agents that find, assess, and fix autonomously. And this week's disclosures show the reuse cycle on the attacker side has compressed to a matter of months: a technique proven in a criminal subscription product in the spring is running against hotel Wi-Fi networks on behalf of a state intelligence service by late summer.

Weston's keynote title captures the state this series has been documenting from different angles for eleven issues now. Rare, expensive, hard to replicate offensive capability was the assumption most defensive postures were built around. That assumption is the thing actually eroding, not any single vulnerability or campaign. The organizations adapting fastest are treating specific technique disclosures, device code phishing chief among them this quarter, as immediate, universal controls to implement rather than as reports about someone else's incident.


FOR DISCUSSION

1. The same OAuth device code phishing technique has now been used by a criminal phishing-as-a-service platform and a Russian state intelligence sub-cluster within roughly three months of each other. How quickly does your organization move from a technique disclosure affecting one threat actor type to a control that addresses all threat actor types using it?

2. CaptiveCrunch manipulates DNS at the captive portal level to deliver malware through fake update prompts on hotel Wi-Fi. Does your travel security guidance address this specific mechanism, or does it stop at generic public Wi-Fi caution?

3. David Weston's keynote argues that AI is eroding the assumption that defenders can patch faster than attackers discover. Is your security program's roadmap built around structural changes, memory safe development, formal verification, automated remediation, or is it still built primarily around faster detection and response within the existing architecture?
