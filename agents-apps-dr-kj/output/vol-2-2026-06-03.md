THE AGENT IS THE NEW ATTACK SURFACE


Microsoft Build 2026 landed on June 2 with a security story that deserves the full attention of every CISO and security architect in a Microsoft environment. The announcements were not incremental. They represent Microsoft's most complete articulation yet of a security architecture designed specifically for the agentic era, one that spans the moment a developer writes the first line of agent code to the moment that agent executes a task against live enterprise data.

Three developments stand out and deserve to be read together. The first is the general availability of the Agent 365 SDK, which went GA on May 1 and received significant Build-stage enhancements this week. [1] The second is the expanded preview of the Microsoft Execution Containers SDK, codename MXC, which brings OS-level runtime containment to agents running on Windows and WSL. [2] The third is Purview runtime DLP for agent prompts in Foundry, now in preview, which intercepts sensitive data before an agent processes it. [3]

Taken individually, each is a meaningful capability. Taken together, they form the first coherent developer-side security stack for AI agents in the Microsoft ecosystem.


THE STAKES


Security teams that have spent the past two years hardening identity, endpoints, and cloud posture are now facing an exposure surface they did not design for: the autonomous agent.

Unlike traditional applications, agents operate with delegated identity, take multi-step actions across systems, interpret natural language instructions, and can be invoked by users, other agents, or automated pipelines. They move data. They execute code. They call external APIs. And in most current deployments, they do all of this with limited observability and even less governance.

Shadow AI has evolved from employees using consumer tools to employees deploying agents that act on behalf of the organization. VentureBeat reported this week that Microsoft's decision to take Agent 365 out of preview was directly accelerated by the growth of unsanctioned agent deployments inside enterprise environments. [4] The question for security leaders is no longer whether agents will be part of the environment. They already are. The question is whether the security architecture will catch up before a material incident forces the issue.


WHAT MICROSOFT IS BUILDING


The Build 2026 announcements sketch a four-layer response. Understanding each layer matters for evaluating how far the coverage extends and where gaps remain.

1. Development-time controls through Agent 365 SDK and Foundry. Developers building agents with the Agent 365 SDK can now instrument observability, access controls, and compliance enforcement directly into the agent at build time. Purview data risk signals embedded in the Foundry Control Plane, now generally available, surface guidance on where to enforce protections before agents ever reach production. [3] This is a shift from reactive detection to preventive design. Security teams that engage with developer workflows will find an integration surface that did not exist a year ago.

2. Runtime containment through the Microsoft Execution Containers SDK. The MXC SDK, now in early preview, provides a cross-platform policy-driven execution layer for agents on Windows and WSL. Developers declare containment policy; the OS enforces it through process and session isolation. [2] For organizations running local agents, whether Copilot-embedded or custom-built, this addresses a class of risk that network controls alone cannot reach. Windows 365 for Agents, also generally available this week, extends this to fully isolated Cloud PCs for agent workloads requiring the highest containment level.

3. Data-in-motion protection through Purview runtime DLP. Purview now applies DLP policy to agent prompts themselves, detecting, blocking, and auditing sensitive data before it is processed by the model. [3] This is a material capability for organizations in regulated industries where the prompt itself can constitute a data disclosure event. The integration runs through Foundry and requires Agent 365, but for organizations already in that stack, the coverage is significant.

4. Telemetry and detection through Sentinel and Security Copilot. On the operational side, the Agent 365 connector for Microsoft Sentinel, now in public preview, pipes AI agent telemetry into the Sentinel data lake as standardized signals, positioning agent behavior alongside identity, endpoint, and cloud activity in a unified investigation workflow. [5] Security Copilot adds five new or enhanced agents this month, including a refreshed Conditional Access Optimization Agent now capable of enforcing least-privilege policies for third-party agent identities, and a Data Security Posture Agent with new credential scanning capabilities. [6] Security Copilot is now included in Microsoft 365 E5 and E7 at no additional cost, a licensing change that removes the primary adoption barrier for enterprise security teams.


WHERE THE COVERAGE IS INCOMPLETE


Transparency requires noting what these announcements do not yet resolve.

The MXC SDK is in early preview. Runtime containment for local agents is a meaningful gap in near-term production environments. The Agent 365 Sentinel connector is in public preview, which means the telemetry schema and ingestion behavior are still subject to change. Organizations building detection rules or workbooks against agent telemetry today should design for schema revision.

The 70-plus partner agents now available in the Security Store through Security Copilot represent an expanded signal surface, and an expanded governance challenge. Each partner agent carries its own data handling practices. Security architects should treat Security Store agents with the same third-party risk rigor applied to any SaaS integration.


THE ROAD AHEAD


The trajectory here is clear. Microsoft is converging its security platform around the agent as the new unit of risk, replacing the user, the device, and the application as the primary governance object. Entra now manages agent identity. Intune and Defender will add runtime blocking and alerts for agent behavior in public preview this month. Purview enforces data policy at the prompt layer. Sentinel monitors the telemetry. Security Copilot automates the response.

What remains is the hard work of organizational readiness. Knowing the platform capabilities is necessary but not sufficient. The CISOs who will be ahead of this are the ones standing up an agent inventory process now, before the architecture decisions that will define the next three years get made by default.


FOR DISCUSSION

1. Your organization likely has agents already deployed that were never reviewed by security. What process do you have today for discovering and inventorying AI agents operating under user or service identities?

2. The Agent 365 SDK puts security controls in the hands of developers at build time. How mature is the relationship between your security team and your developer organization when it comes to integrating controls into the development workflow rather than layering them on afterward?

3. Microsoft's inclusion of Security Copilot in M365 E5 and E7 removes the cost barrier but not the readiness barrier. What would need to be true in your SOC before automated agent-driven response actions would be trusted to execute without analyst review?
