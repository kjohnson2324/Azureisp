THE VOLUME MICROSOFT WARNED YOU ABOUT


Microsoft's July 2026 Patch Tuesday shipped fixes for more than 570 vulnerabilities, roughly triple June's already elevated count and the largest release in the program's history. [1] Microsoft had told customers this was coming. The company disclosed that it is now running MDASH, a multi-model agentic scanning harness that uses multiple AI models to scan critical binaries and validate candidate vulnerabilities before attackers find them, and it warned plainly that AI-assisted discovery means higher patch volume becomes the norm, not a one-time spike. [2]

The same release carried two vulnerabilities that were already being exploited before the patch existed: CVE-2026-56164, an unauthenticated, network-based privilege escalation flaw in SharePoint Server, and CVE-2026-56155, a local privilege escalation flaw in Active Directory Federation Services. [3] Both are actively exploited. Both carry federal remediation deadlines within two weeks of disclosure.

And a third SharePoint issue, CVE-2026-55040, a critical JSON Web Token authentication bypass with a CVSS score of 9.1, was disclosed as half of an exploit chain built for the Pwn2Own Berlin competition. Microsoft patched the authentication bypass this cycle. The remote code execution component of the same chain will not be fixed until the August update. [4]

Three developments, one operating lesson. AI-driven discovery is catching more vulnerabilities before disclosure, which is unambiguously good. It is also producing a patch volume that most organizations' current triage capacity was not built to absorb, at the same time attackers continue to find and use their own footholds in the gap. Volume and urgency are now arriving together, not in sequence.


MDASH AND THE MATH OF MORE BUGS


The scale of the July release deserves examination on its own terms. Roughly 570 vulnerabilities were addressed, including 254 elevation of privilege issues, 145 remote code execution flaws, 102 information disclosure issues, 35 denial of service bugs, 17 security feature bypass vulnerabilities, and 16 spoofing flaws, with 59 rated Critical. [1] That breakdown matters because elevation of privilege, not remote code execution, is now the largest single category. Attackers increasingly do not need an initial remote foothold when a local or adjacent privilege escalation chain is available and undercounted in most threat models built around perimeter breach.

Microsoft attributes the volume increase directly to MDASH. The system scans critical binaries and uses multiple AI models to cross-validate candidate findings before they are reported, a process designed to reduce false positives while increasing the surface area actually reviewed. [2] Microsoft's own statement on the record is direct: as AI helps defenders discover more issues, customers will see a higher volume of security updates in each release. That is a forward statement about every future Patch Tuesday, not a one-time explanation for July.

The operational implication is a capacity question, not a technical one. Patch management programs built around an assumption of roughly 100 to 200 monthly CVEs, a range that held for years, now need to plan around releases that can run several times that size with little advance warning of which month will spike. Triage processes that rank vulnerabilities primarily by CVSS score and RCE classification will systematically underweight elevation of privilege chains, which the July data shows are now the plurality finding, not the exception. Programs that have not revisited their triage criteria against this shift are prioritizing against last year's threat model.


TWO ZERO-DAYS, TWO DEADLINES


The urgent half of this release is the pair of vulnerabilities exploited before Microsoft published a fix.

CVE-2026-56164 affects SharePoint Server and requires no authentication and no user interaction. A remote attacker can use it to escalate privileges directly, which combined with SharePoint's typical placement inside the corporate network, makes it a direct path from external access to elevated internal privileges. [3] CISA's remediation deadline for federal civilian agencies is July 17, 2026, one day after this issue's publication date. [3]

CVE-2026-56155 affects Active Directory Federation Services and requires local access, but the outcome, administrator privileges on an ADFS server, is severe given ADFS's role as a federation trust anchor for hybrid identity environments. An attacker who compromises an ADFS server at that privilege level can potentially forge tokens trusted across every federated relationship the server maintains. [3] The federal deadline for this vulnerability is July 28, 2026. [3]

Organizations running on-premises SharePoint Server or ADFS should not wait for a scheduled maintenance window to apply these two patches. Both are confirmed under active exploitation, and the federal deadlines, while not binding on private sector organizations, are a reasonable floor for any environment with meaningful exposure.

The third SharePoint issue, CVE-2026-55040, requires a different kind of attention. Rapid7's Stephen Fewer built the authentication bypass as one half of a two-vulnerability chain that achieves unauthenticated remote code execution when both halves are combined, originally developed for the Pwn2Own Berlin competition. [4] Microsoft's July release closes the authentication bypass half. The remote code execution half is scheduled for the August release. [4] Because proof of concept research for chained exploits tends to circulate faster than official patches once one half of a chain becomes public, organizations should treat August's SharePoint update as a mandatory same-day priority rather than a routine patch, and should consider interim mitigations, including restricting SharePoint Server network exposure, in the intervening weeks.


THREE ITEMS REQUIRING IMMEDIATE ATTENTION


1. Patch CVE-2026-56164 and CVE-2026-56155 without delay. Both are under active exploitation now, affect infrastructure, SharePoint Server and ADFS, that sits deep inside identity and collaboration workflows, and carry federal deadlines of July 17 and July 28, 2026 respectively. [3] Any organization running either product on premises should treat patch confirmation as a same-week action, not a maintenance-window item.

2. Prepare now for the August SharePoint remote code execution patch. CVE-2026-55040's authentication bypass is fixed. Its RCE pairing is not, and will arrive in the August release as part of a chain already demonstrated at Pwn2Own Berlin. [4] Security teams should flag August's SharePoint update for same-day deployment ahead of time and evaluate reducing SharePoint Server's network exposure until that patch lands.

3. Revisit patch triage criteria against the elevation of privilege shift. With 254 of July's roughly 570 fixes classified as elevation of privilege, the largest single category, and with Microsoft signaling that AI-driven discovery will keep patch volume elevated going forward, [1] [2] triage models weighted primarily toward remote code execution and perimeter exposure should be updated to weight privilege escalation chains and internal lateral movement paths more heavily.


THE ROAD AHEAD


SharePoint's recurrence in this series is not a coincidence of coverage. Vol. 7 covered a SharePoint deserialization flaw that Microsoft rated exploitation "less likely" before CISA confirmed active exploitation eight weeks later. This issue covers a SharePoint privilege escalation flaw that was already being exploited at disclosure, and a SharePoint authentication bypass with its most dangerous component still one release away. The product keeps reappearing because it sits at the intersection every attacker wants: broad internal access, direct internet exposure in many deployments, and a large enough codebase that new classes of flaws keep surfacing.

The Defender Experts Threat Intelligence service Microsoft introduced this cycle is a direct response to the same pressure this issue documents. [5] Its stated purpose is closing the distance between knowing a threat exists and acting on it, delivered as expert-curated, organization-specific guidance rather than raw signal. For security teams facing a patch volume that is now structurally larger than it was a year ago, that kind of curation is not a convenience. It is becoming a capacity requirement.

The throughline across recent issues holds here too. AI is expanding what defenders can find, and it is expanding what attackers can weaponize, at the same time. The organizations keeping pace are the ones that have adjusted their triage capacity and criteria to match the new volume, not the ones still running last year's assumptions about how many vulnerabilities show up in a typical month.


FOR DISCUSSION

1. Microsoft has stated that AI-assisted vulnerability discovery will make higher patch volumes, like July's roughly 570 fixes, the ongoing norm rather than an anomaly. Has your patch management program's capacity planning been updated to reflect that, or is it still sized against a smaller historical baseline?

2. Elevation of privilege vulnerabilities were the largest single category in July's release, ahead of remote code execution. Does your vulnerability triage process weight privilege escalation and lateral movement risk as heavily as it weights remote, unauthenticated exploitation?

3. The remote code execution half of the CVE-2026-55040 SharePoint exploit chain will not be patched until August, with proof of concept research already public from Pwn2Own Berlin. Does your organization have a plan to deploy that patch the day it ships, and have you evaluated interim network exposure reductions for SharePoint Server in the meantime?
