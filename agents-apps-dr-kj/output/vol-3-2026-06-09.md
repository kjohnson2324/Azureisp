Vol. 3 | June 9, 2026


IDENTITY IS THE CONTROL PLANE


Identity has always been the foundation of Zero Trust. Every meaningful security architecture decision in a Microsoft environment for the past decade has eventually come back to the same question: who, or what, is making this request, and should it be trusted?

This week, three developments confirm that Microsoft is extending that foundation to cover the agent layer. The first is the general availability of shadow AI detection and prompt injection protection in Microsoft Entra Internet Access, delivering enforcement where unsanctioned agents enter the network. [1] The second is a confirmed July 2026 milestone for the Sentinel-to-Defender portal transition, which consolidates identity and threat signals into a single investigation surface for the first time. [2] The third is today's Patch Tuesday, June 9, 2026, which includes a patched remote code execution vulnerability in Microsoft 365 Copilot, a pointed reminder that agentic surfaces now appear in the CVE feed alongside traditional applications. [3]

Taken together, these developments do not represent a new direction. They represent the same direction accelerating.


THE IDENTITY PROBLEM FOR AGENTS


The security architecture that governs users and devices was built on a stable assumption: identities are human, and humans can be held accountable for their actions. That assumption is breaking down.

AI agents do not authenticate once and then act. They chain tool calls, spawn sub-agents, re-invoke on triggers, and operate on behalf of users who may not be aware of the full scope of what they authorized. When an agent uses a service principal, that identity often carries permissions scoped for a human workflow, far broader than the agent needs, and with no mechanism for the identity governance processes that would flag the excess.

Microsoft's Entra team put the number in sharper relief at RSAC 2026: organizations that have deployed Copilot Studio agents typically have no formal inventory of what those agents can access. The agents run under service accounts created during deployment and then forgotten. When those accounts are eventually audited, the access scope rarely survives review. [1]

The challenge is that the tools for managing this risk, Conditional Access, Privileged Identity Management, lifecycle workflows, were designed for identities that log in, act, and log out. Agents do not behave that way, and patching human-identity tooling onto agent behavior produces governance theater more than actual control.

Microsoft Entra Agent ID, announced at RSAC and now in active rollout, is the architectural response to this problem.


WHAT MICROSOFT IS DOING


Three capabilities this week deserve direct attention from security architects.

1. Entra Agent ID and Conditional Access for agents. Microsoft Entra now assigns unique identities to AI agents built through Microsoft Foundry, Copilot Studio, and the Agent 365 SDK ecosystem, treating them as first-class principals alongside users and devices. [1] This matters in practice because it means Conditional Access policies can be written for agents specifically, not just for the users who invoke them. The Conditional Access Optimization Agent, which was enhanced last week, can now enforce automated least-privilege policies for third-party agent identities as well as first-party ones. Organizations already running Conditional Access policy management through Security Copilot will see agent identity governance begin to surface in the same workflow as user and device governance.

2. Shadow AI detection and prompt injection protection, now generally available. These two capabilities in Entra Internet Access close a significant gap that has existed since agents began appearing in enterprise environments. Shadow AI detection works alongside Microsoft Defender for Cloud Apps to identify unsanctioned AI applications in use across the organization, monitor usage patterns, and feed Conditional Access with the context needed to enforce policy. Prompt injection protection blocks malicious instructions embedded in external content before they reach the agent model. [1] Both capabilities are generally available as of this week. For organizations in the early stages of building an agent governance program, these two controls represent the fastest path to meaningful coverage, they require no changes to agent code and no new licensing beyond existing Entra and Defender subscriptions.

3. Sentinel in the Defender portal: the July milestone. Starting in July 2026, all new Microsoft Sentinel environments will be created exclusively through the Microsoft Defender portal. The Azure portal remains operational for existing workspaces until March 31, 2027, but the direction is final. [2] The security architecture implication is more significant than the portal change alone suggests. In the Defender portal, Sentinel and Defender XDR share an incident queue, a unified investigation graph, and an analytics engine that spans signals from both products. Agent telemetry, now flowing through the Agent 365 Sentinel connector in public preview, enters that unified surface alongside identity events, endpoint signals, and cloud activity. For security teams building detection coverage for agent behavior, the July milestone is the right time to begin that work in the Defender portal rather than in Azure.

One operational note on the migration: Unified RBAC is mandatory for the Defender portal, and legacy Microsoft Sentinel roles do not carry over. Organizations managing complex RBAC configurations in the Azure portal should plan that migration explicitly before the March 2027 deadline rather than treating it as a portal redirect.


A TIMELY REMINDER FROM PATCH TUESDAY


Today's Patch Tuesday included a patched remote code execution vulnerability in Microsoft 365 Copilot, disclosed on June 4 as part of Microsoft's early security update cycle. [3] The flaw was mitigated in the service before the public advisory, which means the exploitation window was limited. But the advisory itself carries a signal worth reading carefully.

Microsoft 365 Copilot is now a CVE-bearing surface. That means vulnerability management programs that do not currently include Copilot and agent surfaces in their scope are operating with an incomplete asset register. The patch cycle for service-delivered AI components does not follow the same model as endpoint patches, organizations do not deploy these fixes; Microsoft does. But the security team still needs a process for tracking advisory releases, assessing blast radius, and determining whether any of their Copilot configurations expose them to the class of vulnerability described.

The June 2026 Patch Tuesday also includes the final set of patches before the Secure Boot certificate validation deadline of June 26, 2026. Systems that have not completed the Secure Boot certificate update by that date will stop receiving boot-critical security updates and malware blacklists. [4] This is an endpoint hygiene issue, not an agent security issue, but it affects the integrity of the platform on which agents run.


THE ROAD AHEAD


The pattern visible across this week's developments points toward a single structural change in how enterprise security architecture will need to operate: the identity governance process must become the agent governance process.

That means agent discovery feeding into Entra identity lifecycle workflows. It means Conditional Access policies written with agent principals explicitly in scope. It means the Sentinel agent telemetry connector becoming part of the standard SOC data model, not an experimental add-on. And it means that Patch Tuesday briefings now need to include a standing agenda item for AI and Copilot surface advisories.

None of this is technically complex. The platform capabilities are largely in place or entering general availability. The gap is procedural, the processes that security teams run have not been updated to include agents as a governed class of identity, and until they are, the platform capabilities will exist without being exercised.

The organizations that close that procedural gap in the next 90 days will have a material advantage when the first significant agent-related incident surfaces in their industry. The ones that wait for the incident to prompt the process change will spend the next 18 months in catch-up mode.


FOR DISCUSSION

1. Does your organization's Conditional Access policy set include any policies written specifically for agent identities, or are agents currently inheriting policies designed for human and device principals?

2. The Sentinel-to-Defender portal migration is ultimately a data and detection architecture decision. Has your security team assessed what detection rules, workbooks, and automation playbooks will need to be rebuilt or validated in the Defender portal environment?

3. Today's Patch Tuesday included the first broadly publicized Copilot RCE advisory. Does your vulnerability management program have a defined process for tracking and assessing AI and Copilot surface advisories, separate from your standard endpoint patching workflow?
